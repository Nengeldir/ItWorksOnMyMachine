# Wind Rider: final review before unit testing and playtesting

Date: 2026-10-11. Branch: `final-review` (from `Pengyue` at `cbd8501`).
Reviewer: Claude (Claude Code), asked for a feature-by-feature, file-by-file
pass over every visual and gameplay aspect before the team's own unit tests
and playtests.

How to read this: each section is one feature area. Every row says what was
checked, how (code reading, an automated test, or a look in Chrome on the dev
server), and the verdict:

- **OK**: works and looks as intended.
- **Fixed**: a bug found here and fixed in this branch (commit named).
- **TODO**: found, not fixed here; see [Patch notes](#patch-notes-for-what-is-left)
  for how to continue.
- **Note**: not a bug, but worth knowing before playtesting.

## How the review was done

1. Ran the whole toolchain first (build, lint, both test suites) to get a
   baseline.
2. Read the code feature by feature: backend (all five modules), the frontend
   shell (routing, storage, API and profile clients), `Game.ts` end to end, the
   flight model, input and bindings, camera, the run loop (`run/`), abilities,
   items, pickups, the persistent collection, pets, cosmetics, the avatar's
   pose system, effects (pilot FX, particles, portal, finale), the UI
   components and sessions. World generation (frozen for Sky Isles and covered
   by hash tests) was reviewed through its public functions and by looking at
   every biome rather than line by line.
3. Mechanical sweeps over the whole source: modules nothing imports, GLSL
   `pow()` calls whose base can go negative (CLAUDE.md's shader-safety rule),
   allocations inside per-frame methods (rule 7).
4. Drove the game in Chrome on the Vite dev server with a scratch backend
   (separate data directory). The automation tab is hidden to Chrome, so
   `requestAnimationFrame` is throttled; frames were stepped by hand at 60 fps
   (`Game.loop` called with synthetic timestamps), the way `__run` does it.
   Fixed camera views used `__shot`.

## Patch notes for what is left

Items marked "follow-up" above are scheduled in the improvements that come
right after this review (their own pull request). The rest:

### Trusted login headers (backend)

`extract_user` trusts `X-User-Id`/`X-User-Name` because the VIScon portal
sets them in front of port 8080. Nothing strips a client-sent header, so if
the port is ever exposed directly, logins can be forged. How to continue:
in `frontend/Caddyfile`, inside `handle /api/*`, add
`request_header -X-User-Id` and `request_header -X-User-Name` **only if** the
portal sets the headers on a hop Caddy can recognise (for example a shared
secret header such as `X-Portal-Secret` that Caddy checks with a matcher before
passing the identity on). Alternatively add an environment flag
`TRUST_USER_HEADERS=1` in `docker-compose.yml` and have `extract_user` ignore
the headers when it is unset, so local runs and stray exposures fall back to
guest ids. Test: `test_api.py` with and without the flag.

### Room and adventure growth (backend)

Rooms live in memory and anyone can create one per request. Add a per-IP (or
per-client-id) limit in `RoomManager.get_or_create` (for example at most 20
rooms per creator per hour, and a global cap of a few thousand rooms), and
reply 429 beyond it. Adventures: delete plans older than a week (or keep the
last 50 per user) in `Profiles.start`. The follow-up adds rate limits and
plausibility checks for claims; room limits are separate.

### Bundle size (frontend)

The landing page loads the whole game (biomes, terrain, flora, run code) in
one 1.48 MB chunk. Split by route: `GameScreen` and everything under
`game/world/biomes/` behind `React.lazy` so the menu backdrop's needs load
first; keep `three` in its own chunk (`build.rolldownOptions.output
.codeSplitting` or a manual `chunkFileNames` group). Measure the landing
page's time to interactive before and after.

### ItemFx has no unit test

`ItemFx` builds a canvas texture and trails, so it needs a DOM; the firework
fix was verified in Chrome only. To cover it: add a tiny fake `document`
with `createElement("canvas")` returning an object whose `getContext` returns
a stub 2D context (the controls tests already fake `window`/`document`), then
construct `Equipment` with a stub avatar exposing `slots`, `feet` and
`armPose`, and assert that a firework equipped outside the Comet Tail item
survives `ItemFx.update`.

### Persistent pickups' clearance probes

`Collection.frame` calls `collectionClear` (7 distance-field probes) for every
visible pickup every frame. Cache the result per pickup and refresh it every
0.5 s, as `Items.step` does for run pickups (`clearanceTime`).

## Status after the bugfixes pull request (2026-10-11)

The fixes above (`52e684a`, `7df6b8e`, `b9d039f`, `6c8887d`, `4146a14`,
`f75aa27`) were made on `final-review`; they are now applied to `Pengyue` too.
The patch notes, one by one:

- **Trusted login headers**: done. `extract_user` reads `X-User-Id` /
  `X-User-Name` only when `TRUST_USER_HEADERS=1`; `docker-compose.yml` sets it,
  so the deployed game behind the portal behaves as before, and a stray
  exposure or a local `python app.py` falls back to guest ids. Tested both ways.
- **Room and adventure growth**: done. At most 500 rooms at once and 20 new
  rooms per pilot an hour (429 beyond; joining an existing room is never
  limited); each pilot keeps their latest 40 adventure plans and claims.
- **Bundle size**: not done, on purpose. The landing page's live backdrop runs
  a full `Game` with every biome, so lazy-loading `GameScreen` would not make
  the landing page lighter. Splitting needs the backdrop to show a picture
  first and load the game behind it; left for a later change.
- **ItemFx has no unit test**: done (`tests/itemfx.test.mjs`, with a stub 2D
  canvas): it fails on the code before `6c8887d` and passes after.
- **Persistent pickups' clearance probes**: done. `Collection.frame` refreshes
  each shown pickup's clearance every 0.5 s instead of every frame; collecting
  still checks it live, so what can be collected is unchanged.
- **Pets** (follow-up 12): done. The pet plays round the pilot instead of
  holding one spot, and the jump onto and off the hoop rail is gone.
